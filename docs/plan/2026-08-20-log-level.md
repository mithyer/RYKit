# Log Level Filtering Implementation Plan

> **Scope:** Add five-level filtering to `Log.swift`. Keep existing convenience logging functions and the current `LogRecorder` buffering behavior unchanged.

**Goal:** Allow callers to pass a log level to a common `log` entry point, configure the minimum level that is emitted, and skip lower-level messages before they are evaluated or printed.

**Selected level order:** `verbose < debug < info < warn < error`

**Default configured level:** `.debug` for `DEBUG` builds and `.error` for non-`DEBUG` builds.

**Filtering rule:** A message is eligible when `messageLevel >= configuredLevel`. In `DEBUG`, `debug`, `info`, `warn`, and `error` are eligible. In non-`DEBUG` builds, only `error` is eligible.

---

## Current State

- `Classes/Core/Log/Log.swift` currently exposes `log_info`, `log_warn`, and `log_err`.
- `LoggerProtocol.log_plain` receives a `LogType`, message, interval-throttling parameters, and source metadata.
- `DefaultLogger` currently forwards messages to `LogRecorder` only in `DEBUG`; its `#if DEBUG` guard suppresses all default-logger output in non-`DEBUG` builds. No configurable level exists yet.
- `LogType` currently contains `info(String?)`, `warn(String?)`, and `error(String?)` cases. The associated string is used as the interval-throttling key.
- The repository has no production call sites for the global `log_info` or `log_warn` functions. `CollectionsTests` directly exercises `log_err`.
- `HttpRequest` has a separate private method named `log_err`; it is unrelated and must not be changed.
- `RYKitCoreTests` already targets `Project/RYKitTests/LogRecorder`, so a new log-level test file in that directory can be covered by SwiftPM without changing `Package.swift`.

---

## Fixed Decisions

- Add a public `LogLevel` enum with five ordered cases:

  ```swift
  public enum LogLevel: Int, Comparable, CaseIterable {
      case verbose = 0
      case debug
      case info
      case warn
      case error

      // Compare levels by their declared severity order.
      public static func < (lhs: Self, rhs: Self) -> Bool {
          lhs.rawValue < rhs.rawValue
      }
  }
  ```

  `allCases` and `rawValue` must preserve the order `verbose < debug < info < warn < error`.

- Add a common public `log` function that accepts `level` and a generic key for interval throttling.
- Keep `log_info`, `log_warn`, and `log_err` as compatibility wrappers around the common function.
- Set the default minimum level to `.debug` in `DEBUG` builds and `.error` in non-`DEBUG` builds. This keeps development logs useful while limiting release logging to errors.
- Initialize the default level with compile-time branching:

  ```swift
  #if DEBUG
  private var configuredLogLevel: LogLevel = .debug
  #else
  private var configuredLogLevel: LogLevel = .error
  #endif
  ```

- Do not retain the old `DefaultLogger`-only `#if DEBUG` suppression. The configured level is now the build-mode gate, so release `.error` messages can still reach the logger. This intentionally changes release behavior: accepted messages are buffered by `LogRecorder` and eligible errors may create or append to files under `Documents/RYKitLogs` when its buffer flushes. This change does not add a public flush hook for the default recorder.
- Use an `@escaping @autoclosure` for the common entry point and the compatibility wrappers. Filter before invoking that autoclosure. A filtered message must not perform interpolation, serialization, or other message construction work.
- Filter before calling `activeLogger`, while passing the still-deferred message expression to `LoggerProtocol.log_plain` so the existing recorder can continue to apply interval throttling before evaluating content.
- Keep `LoggerProtocol.log_plain`'s parameter shape. The level is represented through the expanded `LogType` passed to the existing protocol method.
- Protect the configurable level and active logger adapter with dedicated locks so concurrent threshold/logger changes and log dispatches do not race.
- Do not change `LogRecorder`'s buffering, file format, flush behavior, or interval-throttling implementation.

## Proposed Interface

### Log level configuration

Add a public setter:

```swift
public func setLogLevel(_ level: LogLevel)
```

The configured value is process-wide, matching the existing process-wide `activeLogger` configuration model. The implementation should keep the mutable state private and expose only the setter unless a read accessor is needed by the existing style.

### Common log entry point

Add a common entry point equivalent to:

```swift
public func log(
    _ message: @escaping @autoclosure () -> CustomStringConvertible,
    level: LogLevel,
    key: String? = nil,
    minIntervalBetweenSameKey: TimeInterval? = nil,
    file: StaticString = #fileID,
    line: Int = #line,
    function: StaticString = #function
)
```

The implementation will:

1. Read the configured minimum level under the level lock.
2. Return immediately when the message level is below the configured level.
3. Do not evaluate the escaping autoclosure while the message is filtered.
4. Convert the level and key into an associated-value `LogType`, preserving the key for all five levels.
5. Forward the still-deferred message expression and source metadata to `activeLogger.log_plain`; the logger/recorder remains responsible for evaluating the content after any interval-throttling decision.

### Existing convenience functions

Preserve the current public function names, key parameters, and level mapping, but express their message parameter as an escaping autoclosure so filtering also prevents caller-side interpolation for these wrappers:

```swift
public func log_info(
    _ message: @escaping @autoclosure () -> CustomStringConvertible,
    infoKey: String? = nil,
    minIntervalBetweenSameKey: TimeInterval? = nil,
    file: StaticString = #fileID,
    line: Int = #line,
    function: StaticString = #function
)
```

Apply the same message-parameter shape to `log_warn` and `log_err`. Direct call sites remain source-compatible; callers that store these functions as values must be checked because the function type changes. Each wrapper forwards to the common entry point without evaluating the message and must explicitly pass its captured `file`, `line`, and `function` arguments so caller source metadata is preserved:

- `log_info` forwards to `.info`.
- `log_warn` forwards to `.warn`.
- `log_err` forwards to `.error`.

Their current direct call sites should not require changes.

### Log type mapping

Extend `LogType` with associated-value cases for all five levels, retaining the existing key channel:

```swift
case verbose(String?)
case debug(String?)
case info(String?)
case warn(String?)
case error(String?)
```

The associated `String?` is the interval-throttling key. Preserve the existing output labels for the current levels:

- `[#INFO#]`
- `[#WARN#]`
- `[#ERROR#]`

Use corresponding labels for the new levels:

- `[#VERBOSE#]`
- `[#DEBUG#]`

The recorder key should continue to be derived from the complete log type so interval throttling remains level-specific and key-specific for all five levels.

## Implementation Steps

### Step 1: Add the level interface

Modify `Classes/Core/Log/Log.swift` to add `LogLevel`, the process-wide level state, `setLogLevel`, and the common `log` entry point. Keep the filtering logic concentrated in this file so callers do not implement their own level checks.

### Step 2: Preserve existing logging behavior

Route the three existing convenience functions through the new entry point. Each wrapper must pass its captured `file`, `line`, and `function` values explicitly when forwarding, so the common entry point does not replace caller metadata with wrapper-site defaults. Verify that `DefaultLogger` forwards eligible logs in both build modes: `DEBUG` defaults to `.debug`, while non-`DEBUG` defaults to `.error`. Interval throttling should continue to receive the same type-derived key.

### Step 3: Add focused tests

Add `Project/RYKitTests/LogRecorder/LogTests.swift` with a custom `LoggerProtocol` test adapter. The adapter should capture the forwarded message, `LogType`, interval value, and `file`/`line`/`function` metadata in a thread-safe test buffer.

Cover:

- `LogLevel.allCases` and raw-value ordering equal `[.verbose, .debug, .info, .warn, .error]`; verify `Comparable` follows that order.
- Build-specific default behavior: in a `DEBUG` test build, the default `.debug` accepts `debug`, `info`, `warn`, and `error` while filtering `verbose;` in a non-`DEBUG` test build, the default `.error` accepts only `error`.
- Explicit `.verbose` configuration forwards all five levels.
- Explicit `.debug` configuration filters only `verbose`.
- Explicit `.error` configuration forwards only `error`.
- Changing the configured level takes effect for subsequent calls.
- A filtered autoclosure passed to `log` is not evaluated, and the same holds for the three compatibility wrappers.
- `log_info`, `log_warn`, and `log_err` retain their existing level, key, interval, and source-metadata forwarding behavior.
- Each `LogType` case retains its associated key and expected description, including the existing three labels.
- A concurrent `setLogLevel`/`setActiveLogger`/`log` smoke test exercises both configuration locks without requiring an exact ordering of concurrently emitted messages.
- Test teardown restores `DefaultLogger` and the compile-time default (`.debug` in `DEBUG`, `.error` otherwise). Since there is no public getter, teardown resets to the build default rather than restoring an arbitrary previous value.
- Keep global logging calls unqualified in the Xcode test target because the target compiles `Classes` directly and also links the framework; this avoids mutating a duplicate copy of the process-wide state.

Use the same conditional module import pattern as `LogRecorderTests.swift` so the tests run under both SwiftPM and the Xcode project. Add `// TEST:` comments at the production seam and test entry points according to repository convention.

### Step 4: Document the interface

Update the README logging section with a short example showing:

```swift
setLogLevel(.warn)
log("cache miss", level: .debug)
log_warn("request retrying")
```

Document that the configured level is a minimum threshold, that `DEBUG` builds default to `.debug`, and that non-`DEBUG` builds default to `.error`. Also document that the default logger buffers accepted messages through `LogRecorder`, writes according to its buffer-size and flush policy under `Documents/RYKitLogs`, and does not expose a new public default-recorder flush hook. Custom adapters installed through `setActiveLogger` are filtered by the same threshold.

The current README contains an outdated `LogRecorder.shared.saveLog(...)` example. Replace that example with the current `LogRecorder` API or remove it while adding the new level-filtering example; do not leave the nonexistent API in the logging documentation.

### Step 5: Verify

Run:

- SwiftPM tests with `DEBUG` explicitly defined, such as `swift test -Xswiftc -DDEBUG`, to verify the `.debug` default.
- SwiftPM Release tests without `DEBUG`, such as `swift test -c release`, to verify the `.error` default and Release `DefaultLogger` forwarding.
- Xcode Debug log tests on an iOS Simulator or the hosted test target.
- Xcode Release log tests on an iOS Simulator or the hosted test target, using the command-line `ENABLE_TESTABILITY=YES` override because the current project Release configuration does not enable `@testable import`; do not change the product Release configuration as part of this feature.
- Existing `TinyKV`, `TinyBufferedKV`, and relevant regression tests.
- README consistency, including removal or correction of the stale `LogRecorder.shared.saveLog(...)` example.
- `git diff --check`.

## Compatibility Considerations

- Existing direct calls to `log_info`, `log_warn`, and `log_err` remain source-compatible. Changing their message parameter to an escaping autoclosure can affect code that stores these functions as values, so search for such uses before implementation.
- Existing `LoggerProtocol.log_plain` implementations do not need a new required method parameter.
- `LogType` is currently public. Adding associated-value `verbose` and `debug` cases can require external clients with exhaustive `switch` statements to add branches and preserve the key payload. This is the main intentional source-compatibility consideration of the design.
- The private `HttpRequest.log_err` method is outside this change.
- Release builds use `.error` as the default minimum level, so error logs remain eligible for the logger. Removing `DefaultLogger`'s `#if DEBUG` guard intentionally changes the observable behavior from no default log-file writes in Release to eligible error log buffering and file I/O under `Documents/RYKitLogs` when the recorder flushes; this change does not add a public default-recorder flush hook.
- Custom logger adapters are filtered by the process-wide configured threshold before `activeLogger` is called. In Release, an adapter receives only errors by default unless the host calls `setLogLevel` with a lower threshold.
- Tests must reset both the active logger and the build-specific default threshold because the configuration is process-wide and there is no public getter.

---

## Acceptance Criteria

- `LogLevel` exposes exactly five levels in the selected order, has a compiling `Comparable` implementation, and orders values by raw severity.
- The default minimum level is `.debug` in `DEBUG` builds and `.error` in non-`DEBUG` builds; both configurations are covered by explicit test invocations.
- Messages below the configured level are neither evaluated nor forwarded for the common `log` entry point or the three autoclosure compatibility wrappers.
- Messages at or above the configured level are forwarded exactly once through the existing logger seam.
- All five `LogType` cases retain their associated key, expected label, and level-specific interval-throttling behavior.
- Existing convenience functions continue to compile for direct calls and preserve their level, key, interval, and source-metadata semantics.
- Release `DefaultLogger` behavior is intentional and documented: accepted messages are buffered by `LogRecorder`; eligible errors may create or append to `Documents/RYKitLogs` when the recorder flushes, and no new public default-recorder flush hook is added.
- Existing `LogRecorder` file and buffering tests continue to pass.
- New log-level tests pass under DEBUG and non-DEBUG SwiftPM invocations and both Xcode configurations.
- No unrelated production modules are modified.
